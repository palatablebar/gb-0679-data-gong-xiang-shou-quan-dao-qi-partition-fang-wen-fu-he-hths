# 授权定义

资源orders与订单等价，customers与客户等价。principal为主体文本，不支持模糊主体。partition为YYYY-MM；分区授权[start,end)不含end月。授权时间也为[start,end)，到期时刻立即失效。

每条授权包含主体、资源、生效窗、分区窗和allow/deny。全部条件必须同时匹配。拒绝优先，多个允许不能覆盖任何显式拒绝；无匹配默认拒绝。匹配规则ID按字典序稳定排序，冲突显示全部允许与拒绝证据。

observed为真实访问执行结果allowed或blocked；reported为上游0/1判定，留作证据。expected为实际授权复算，分区模块重建reported为执行结果便于二值对账。越权放行和误拦截分别计数，禁止用相互抵消的总数代替逐条核查。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

## 双端时间与唯一有效时点

输入支持两种表头：8列旧表头与含`received_at`（接收端时间）的9列扩展表头；旧表头按接收端缺失处理。`access_time`为生产端来源时间，`received_at`为接收端落账时间，两端原始文本在全流水线与证据导出中原样保留，裁决只派生`effective_at`、`time_basis`、`time_status`、`clock_delta_seconds`、`boundary`字段。时钟容差由参数`clock_skew_seconds`控制，缺省300秒。

裁决（实现见app/timing.py）：双端合法且钟差在容差内互证，采来源时间为唯一有效时点；双端合法但钟差超容差时，若为授权到期边界访问（任一端落在相关授权窗端点±容差邻域，或两端对授权窗内外归属翻转）则留待核、不产生授权/分区/对账结论，非边界访问仍采来源并标记"时差未证"；边界访问缺接收端一律留待核以防到期后伪造；来源时间失效按INVALID_TIME隔离，即使接收端合法也不替代第一证据，接收时间仅随隔离行留痕；双端皆失效不产生有效时点。留待核行进独立pending集合，守恒公式为输入=采纳+隔离+留待核+排除，证据导出kind=pending。

同一event_id重试且仅接收时间/备注不同时，不新增结论：来源行并入首条`_sources`，各次接收时间保留在`_retry_received`。批次payload的任何整段替换在单事务内提交，中断即回滚恢复旧版（见store.replace_payload），双端原始时间随旧版保留。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
